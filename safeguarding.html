Child Safeguarding & Student Data Statement

Publisher: A.I MY · Reference release: Task 8L Full Release Candidate · Runtime: 8J-R2 LIVE PASS · Manifest version 1.9.7 · Release documentation date: 20 September 2026 · Website policy review: 25 September 2026 · Contact: thiaimynguyen734@gmail.com

Important: This statement documents product safeguards. It is not a legal certification and does not replace school policy, safeguarding procedures, data-protection review, or jurisdiction-specific legal advice.

Purpose and audience

Hub Assistant is designed for teachers and authorized school staff using supported PowerSchool / PowerHub educator pages. It is not designed as a student-facing application.

The extension provides contextual guidance while preserving teacher control and keeping PowerSchool / PowerHub as the official source of school data and workflow state.

Safeguarding principles

1. Data minimization

Hub Assistant should access only the page information required to identify the current teacher workflow and provide relevant guidance. The current release does not maintain a persistent student nickname/profile database.

2. Local and transient processing

Student/guardian names, roles, relationship context, class context, and related page state may be processed transiently in the browser when needed for a teacher-facing workflow. The current release does not send this information to an A.I MY backend, analytics service, advertising service, Microsoft Graph, Google Identity, or another cloud identity service.

3. No student profiling or advertising

The current release does not create commercial or behavioral profiles of students, use student information for advertising, display targeted advertising, sell or broker student information, or use student information for unrelated product analytics.

4. Teacher control

The extension may guide intermediate interface actions but does not automatically perform the final consequential action for sending a message, creating a Group Chat, or publishing a Newsfeed post.

5. Identity safety

Where recipient matching is used, the design preserves native/original PowerSchool identity evidence and role matching rather than relying on approximate or nickname matching.

The retirement of the former nickname feature does not remove the shared identity layer required for recipient, guardian-relation, class-mapping, and Group Chat safety checks.

6. Legacy data minimization

The current release includes install/update cleanup for legacy keys studentNicknames, studentProfiles, and psqmStorageVersion. No new persistent student nickname/profile records are created by the current release.

7. No credential collection

The current release is not designed to collect PowerSchool passwords, browser cookies, session tokens, authentication tokens, payment data, or health data.

The audited session-timeout helper does not click Stay Signed In, install a timeout observer/listener, or silently extend a PowerSchool login session.

8. Minimum permissions

The current manifest requests only storage plus host access to https://vas.educator.powerschool.com/*. It does not request <all_urls>, cookies, history, webRequest, debugger, nativeMessaging, geolocation, microphone, camera, or identity-provider permissions.

9. Deployment-neutral safeguarding

Before rollout, the school should assess shared devices/browser profiles, extension administration, PowerSchool authentication, user notice, support, and incident-handling procedures.

10. Screenshots and support material

Store screenshots, training material, bug reports, and support examples should not contain real student or staff personal information. Use sanitized or synthetic demonstration data.

11. Change-control safeguard

A new privacy/safeguarding review is required before releasing a version that adds new permissions, broader host access, analytics/telemetry, an external backend, cloud sync, identity integrations, persistent student/guardian data, automatic final Send/Create/Publish behavior, a student-facing workflow, or new categories of personal/sensitive data.

Tóm tắt safeguarding bằng tiếng Việt

Hub Assistant dành cho giáo viên và nhân viên trường học được ủy quyền. Website policy này được đối chiếu với Task 8L Full Release Candidate (runtime 8J-R2 LIVE PASS, manifest 1.9.7). Build hiện tại không lưu lâu dài cơ sở dữ liệu nickname/hồ sơ học sinh, không dùng analytics/ads, không gửi dữ liệu học sinh tới backend A.I MY và không tự động thực hiện hành động cuối cùng như Send, Create Group hoặc Publish.

Helper session-timeout đã audit không bấm Stay Signed In và không âm thầm kéo dài phiên đăng nhập PowerSchool.

Ngữ cảnh học sinh/người giám hộ chỉ được xử lý cục bộ và tạm thời khi cần cho workflow của giáo viên. Trước rollout, trường cần đánh giá riêng về thiết bị dùng chung, profile trình duyệt, quản trị extension, user notice, support và quy trình safeguarding.
